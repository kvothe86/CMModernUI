# Player Search "Ability" view: findings (exe 3.9.68, VA; file offset = VA - 0x400000 in .text)

Disassembled with capstone from E:\CM0102\cm0102.exe (the Ghidra C drops call arguments). "Not found / not verified" is marked.
Screen: build 0x808690, input 0x80eb00. `esi` in the row code = Staff*, `ebp` = area id, `[esp+0x10]` = row counter.

## 1. View popup (built in 0x808690, inline, no helper per item)
- "View" button: `add_area_button` 0x8040a0 at 0x80a152 (text 0x988004, pushed at 0x80a108). Popup area: `Display::add_area` 0x55fba0 at 0x80a188, returns area id in eax -> esi. Gate: `cmp word [list count],0 / je 0x80ac81` at 0x80a115.
- Every item = `sprintf(0xde1f64, text)` (langlib_sprintf 0x66f4e0) then `Display::add_item` 0x55f990 (thiscall ecx=[0xb74c4c+chan*0x300], 18 stack args, ret 0x48). add_item args (arg1 first): type, 6x0, 0x10, [ae31aa], [aebdec], 1, 1, [aebdea], **text=0xde1f64**, 0, **id=0x12**, **data=view bit**, area.
- Tick: inline `test al,bit` on `*[0xdd6cc8]` (low byte of the view dword). Ticked -> type **0x2002**, else **2**. (0x456890 add_ticked_popup_item is the same call with type 0x2002 fixed; the build does not call it.)
- Items in menu order (all after `call 0x66f4e0`; text has 2 leading spaces; data = bit):

| item | text ptr | sprintf call | add_item call | data/bit |
|---|---|---|---|---|
| General | 0xa7e71c | 0x80a199 | 0x80a23a | 0x01 |
| Contract | 0xa7e710 | 0x80a26a | 0x80a30b | 0x40 |
| Stats | 0xa7e708 | 0x80a31a | 0x80a3bb | 0x02 |
| More Stats | 0xa7e6f8 | 0x80a3ca | 0x80a46b | 0x04 |
| Attributes | 0xa7e6e8 | 0x80a47a | 0x80a51b | 0x08 |
| Scout Report (only if `[slot+0x191] > -1`, i.e. a scout assigned, check 0x80a536) | 0xa7e6d8 | 0x80a54e | 0x80a5f3 | 0x2000 |
| Player Notes | 0xa7e6c8 | 0x80a602 | 0x80a6a3 | 0x10 |
| Other (skipped for list type 3 = staff search, check 0x80a6be) | 0xa7e6c0 | 0x80a6d3 | **0x80a774** | 0x20 |
- Contract/Stats/More Stats are also skipped for list type 3 (check 0x80a255). List type `[slot+0xb]`: 1 short list, 2 player search, 3 staff search, 4 scout list.
- Attributes sub-popup (Physical 0x80, Mental 0x100, GK 0x200, Def 0x400, Att 0x800, Filtered 0x1000, "Non Playing" 0x80 for type 3) is built only `if flags&8` (0x80a77f); same id 0x12.

## 2. Where the view is stored
- Session = `ScreenManager(0xb74450)::get_screen_param(0)` (0x7ff010; first byte `[s]` = current tab 0..9; slot stride **0x2b0**). View dword at **`s + [s]*0x2b0 + 0x294`**, per tab. Global pointer to it: **`DAT_00dd6cc8`** (set at 0x808ac0, also at the top of 0x80eb00 line `DAT_00dd6cc8 = ...+0x294`). It sits right after the 0x99-byte filter block (copied at 0x808bd1..0x808be2).
- Layout: `+0` view dword, `+4` sort key (dword), `+8` byte, `+9` byte, `+0xa` reverse-sort flag (dword), `+0xe` page (short).
- View = **one-hot bit mask**, not 0..6: General 0x01, Stats 0x02, More Stats 0x04, Attributes 0x08, Player Notes 0x10, Other 0x20, Contract 0x40, Physical 0x80, Mental 0x100, GK 0x200, Def 0x400, Att 0x800, Filtered 0x1000, Scout Report 0x2000. Bits 0x4000+ unused by this screen (search of both .asm: no test of 0x4000/0x8000 on this dword; **not checked**: other code, save/load of PLAYER_SEARCH).
- Default/repair: 0x808ac8..0x808af8: if 0x2000 set and no scout -> subtract 0x2000, or in 1.

## 3. Click on a View item (0x80eb00; arg = clicked widget index, short, -1 = none)
- Not index arithmetic: the view bit travels in the item's **data**. Item id at `chan + 0xba966 + idx*0x18c` (short), data at `chan + 0xba9a6 + idx*0x18c`, chan = `[0xb74c4c + [0xb77c7a]*0x300]` (0x8124c2..0x812517). `cmp cx,0x12` at **0x8124eb**.
- Whitelist: data<=0x80: byte table 0x813074 -> dword table 0x81306c: {1,2,4,8,0x10,0x20,0x40} -> **0x81258a**, others -> 0x812c26 (`mov eax,-0xb; ret`, no change). 0x80,0x100,0x200,0x400,0x800,0x1000 -> **0x8125b6**; 0x2000 -> 0x81258a (cmp at 0x81257f, `3d 00 20 00 00 0f 85`).
- 0x81258a: `flags = (flags & 0xffffdf80) | data` (imm32 at 0x812595, file 0x412595: `80 df ff ff`), returns -0xb (= rebuild screen). 0x8125b6: `(flags & 0xffffe07f) | data`.
- So an unknown data value (0x4000) is silently ignored; a hook is needed (or patch 0x81257f/0x812595).

## 4. Columns per view (build 0x808690)
- Order in the build: widths tables (13 bytes, one per view, built from immediates 0x808721..0x808969; sum = 97): General {6,5,0x16,0x14,0x14,0xe,0,0,0,0,0,0,0xa}, **Other {6,5,0x16,8,6,6,6,0xa,0xc,6,0,0,0xa}** (stack `esp+0x88`, used with `lea ecx,[esp+0x98]` after 4 pushes at 0x80c889). Cols: 0 Mat/Rec/Sqd, 1 Inf, 2 Name, 3..11 view cols, 12 Value.
- Sort callback chosen from sort key (`[flags+4]`) at 0x808bf0..0x808e39, passed to `SearchEditSession::get_current_results` 0x804a40 (call 0x808e47; thiscall ecx=session, args out_list, out_count, callback).
- **Header chain** (0x80b84e..0x80d000), flags tested as `test al/ah,bit`, `if`-sequence: General `test al,1` 0x80b84e; Contract 0x40 at 0x80bc17; Stats/More `test al,6 -> 0x80cc99` at 0x80bf18; Attributes `test al,8` 0x80bf20; Scout Report `test ah,0x20` 0x80c444; Player Notes `test al,0x10` 0x80c709; **Other `test al,0x20` 0x80c879**. Each block ends `jmp 0x80d000`. **Unknown bit: `je 0x80d000` at 0x80c87b -> no header area at all** (rows still built, see below).
- Header cell = sprintf(0xde1f64, text) + `add_area_button` 0x8040a0 (this=0xb74450, area, col, row 0, style 0x30, colour [ae317e], flags 0xc, font 1, text colour [ae3184], text, id **0x1e**, data = sort key).
- **General** headers (call site, text, col, sort key): Inf 0x98ea64 c1 key 2; Name 0x98ea5c c2 key 4; Club 0x98ea44 c3 key 8; Based 0xa7e1e8 c4 key 0x20; Position 0x98ea00 c5 key 0x40 (add_button 0x80bb7b); Value 0x98ea0c c12 key 0x100 (0x80bbbe). (Type 3 uses "Club/Nation", "Job", "Rep.".)
- **Other** headers 0x80c881..0x80cc6a: Inf c1 (call 0x80c9c3), Name c2 (0x80ca02), **Nat. 0x98e9e0 c3 key 0x1000 (call 0x80ca45)**, **Age 0x98e9dc c4 key 0x2000 (0x80ca87)**, **Caps 0x98e9d4 c5 key 0x4000 (0x80cac9)**, **I.Gls 0xa7e184 c6 key 0x8000 (0x80cb11)**, **Form 0x98e9f8 c7 key 0x10000 (0x80cb53)**, **Morale 0x98e9f0 c8 key 0x20000 (0x80cb95)**, **Cond. 0x98e9e8 c9 key 0x40000 (0x80cbd8)**, Value 0x98ea0c c12 key 0x100 (0x80cc6a; type 3: "Rep." key 0x200). Header area: `add_area` 0x55fba0 call at 0x80c8b8 (data_len 0xd, data ptr = widths).
- **Row phase** (0x80d000..0x80e950, loop `LLIST::get_current` 0x68d2e0 at 0x80d06f / 0x80e947; `jne 0x80d08b`): common cells first: col 0 Mat/Rec/Sqd, col 1 Inf (`get_player_status_code` 0x4849f0, `ScreenManager::add_item` 0x45cb60 at 0x80d75a), col 2 Name (`database_format_staff_name` 0x53dba0 at 0x80d7a3, style 3, then `add_area_button` col 2 id 0x7d7 data=staff at 0x80d7f7). Then the per-view chain (single-bit `test`, sequential): General `test al,1` **0x80d9b0**; Contract 0x40 0x80dc2d; Stats 2 0x80de8b; More 4 0x80df3b; Attributes 8 0x80dfeb; Scout Report `test ah,0x20` 0x80e127; Notes 0x10 0x80e45d; **Other `test al,0x20` 0x80e56a**. Then the **common Value cell, col 12, at 0x80e774..0x80e8f2** (all views; unknown bit gets only Inf, Name, Value, and the row-click button at 0x80e925).
- **General cells**: col 3 club = `"  %s"` of `club+0x38`, `add_area_button` id 0x7d5 data club (0x80d9c0..0x80d9fe; no club -> "  No Club" 0xa7e06c, 0x80db3f); col 4 Based = nation of club (`[club+0x53]`, else `[staff+0x1a]`), name at +0x38 (0x80da79..0x80dacb); col 5 Position = `database_format_player_positions` 0x53ee50(`[staff+0x61]`, buf, 0xc8, 1) -> `"  %s"` -> `add_area_text` 0x804100, text colour [aebdd4] (0x80dbd8..0x80dc28, jmp 0x80e769).
- **Other cells** (staff in esi; text via `0x944c9f` sprintf; all `add_area_text` 0x804100 (this 0xb74450, area, col, row, style 1, colour 0, flags 0xc, font 2, text colour, text) except col 3): col 3 Nat. = `add_area_button` of national team (`[staff+0x1a]`, 0x53b3d0, text `nation+0x53`, id 0x7d5) **call 0x80e5ac**; col 4 Age `"%d"` of `movsx byte [staff+0x18]` **call 0x80e5ea**; col 5 Caps byte `[staff+0x22]` call 0x80e629; col 6 I.Gls byte `[staff+0x23]` call 0x80e668; col 7 Form `PlayerStats::format_recent_ratings` 0x7c1660(0xb74350, `[staff+0x61]`) call 0x80e6a8; col 8 Morale 0x4cc2e0 call 0x80e701; col 9 Cond. 0x62c400 / 0x62c590, "%d%%" call 0x80e76f. Value (col 12, 0x80e87b..0x80e8f2): if club and `[staff+0x52]`: `Cash::Cash` 0x450a90 + `format_display_amount` 0x450aa0(buf 0xde1f64, size 0x7d0 flags 5) else "Free" 0x98e614; type 3 prints the Superb..Very Poor words from `[entry+0x21]`.
- Default branch for an unknown view: see header chain above (no headers) and rows (Inf, Name, Value only). Nothing is drawn for the other columns.

## 5. Per row data
- List = `LLIST` (out_list of `get_current_results` 0x804a40 at 0x808e47, page via `[flags+0xe]`), iterated by 0x68d2e0/0x68d1b0 (next) / 0x68d1d0 (prev, when `[flags+0xa]` reverse). Entry = 45-byte (0x2d) `search_result` (ebx; saved `[esp+0x40]`).
- Staff*: `idx = [entry+0xc]` (int); `staff = [0xae23bc] + idx*0x6e` (0x80d0d2..0x80d0e4 -> esi). Fields used: +0x18 age (s8), +0x1a nation*, +0x22 caps, +0x23 int goals, +0x24/+0x28 (non-player employer/job), +0x39 club*, +0x3d job, +0x52 value (int), +0x61 PlayerData*. Club: +0x38 name, +0x53 nation*.
- Age: sprintf "%d" (0x944c9f) -> add_area_text col 4. Position: 0x53ee50 -> col 5 (General). Club name: `"  %s"` of club+0x38. Value: Cash 0x450a90/0x450aa0 as above.
- Entry fields (search_result copy 0x7af580): +0xc staff idx, +0x20 flags byte, **+0x21 dword scout-seen current rating, +0x25 dword scout-seen future rating, +0x29 byte current stars 0..5, +0x2a byte potential stars 0..5**, +0x2b, +0x2c bytes (note rating 0xff = none).

## 6. Stars
- 0x819620 `compare_results_by_ability_stars(a,b)`: `b[+0x29] - a[+0x29]` (descending), ties/equal -> `database_format_staff_name` of both (0x53dba0, style 3) and strcmp-like 0x90c1d0; null a -> 1, null b -> -1. 0x8196e0 = same on **+0x2a**. They read only the search_result entry.
- Stars are the **scout's estimate**: written only by `PLAYER_SEARCH::report_on_player` 0x7b62a0 (stores 0x7b6a47 / 0x7b6a4e; thresholds 0x7b687b..0x7b69cf from the reported rating (+0x21/+0x25) vs the judge staff's `word [judge+0x80]`: >=`2*x+0x31ce` -> 5, `+0x29fe` -> 4, `*0x9689b0` -> 3, `*0x968e40` -> 2, else 1/0) and copied by search_result_copy/merge code (0x7af580, 0x7afe46, 0x7b09e1, 0x7b10cc, 0x7b1416, 0x7b171d, 0x7b1fea, 0x7b4294, 0x7bd5c0). `PLAYER_SEARCH::add_player` 0x7af720 (manual shortlist add) sets them to 0, so unscouted players have 0 stars.
- Sorting uses them only when the filter flag mask has bit 0x1000000 (ability stars) / 0x2000000 (potential stars) and sort key == 1 ("Rec" header, scout lists): chain 0x808bf0..0x808ca9. Same flags decide what the "Rec" column shows (stars as "*****" 0xa7e17c.. strings at 0x80d1a5..0x80d1e8, from `[entry+0x29]`/`[entry+0x2a]`, else max of both).
- True ability (not the scout's): `PlayerData = [staff+0x61]`; **CA = s16 at +5, PA = s16 at +7** (see 0x5d6220 compare_players_by_ability, 0x549c30). Stars-from-CA mapping: not found.

## 7. Proposal: "Ability" as Other layout + DLL overlay (smallest)
State: view bit **0x4000 = Ability, kept together with 0x20 (Other)** so the game builds the Other view untouched. `flags = *(uint**)0xdd6cc8`.
1. **Menu item**: redirect the call at **0x80a774** (`e8 17 52 d5 ff` -> own stub, thiscall, 18 stack args, callee pops 0x48). Stub: if `*flags & 0x4000` set arg1 (type) to 2 for the original Other call (un-tick Other); call 0x55f990; then call it again with arg1 = `(*flags&0x4000)?0x2002:2`, arg14 (text) = pointer to a buffer with "  Ability", arg17 (data) = 0x4000 (id arg16 stays 0x12, area arg18 same). Only reached for list types != 3 (same condition as Other).
2. **Click**: hook entry **0x80eb00** (cdecl, int widget; prologue `81 ec 94 07 00 00`). If `(short)widget != -1`: read id/data as in section 3; if id==0x12 and data==0x4000: `*flags = (*flags & ~0x207f) | 0x20 | 0x4000; return -0xb;` (flags ptr = `s + [s]*0x2b0 + 0x294`, s = get_screen_param(0)); if id==0x12 and data in {1,2,4,8,0x10,0x20,0x40,0x2000}: clear 0x4000 first (the game only clears 0x207f), then call the original. (Alternative without the hook for the second part: byte patch 0x412595 `df`->`9f` so the game clears 0x6000, plus patch 0x41257f/0x412584 `cmp eax,0x2000 / jne` -> `test eax,0x6000 / je`; the OR of 0x20 still needs code, so the hook is simpler.)
3. **Draw** (only when `*flags & 0x4000`, match by return address inside the Other blocks; use ESI = Staff* of the caller; remember the entry from `LLIST::get_current` 0x68d2e0 called from 0x80d074 / 0x80e94c, return value in eax = search_result*):
   - widths: hook `Display::add_area` 0x55fba0 for the call at 0x80c8b8 (ret addr 0x80c8bd): replace `data` (arg 6) with {6,5,0x16,0x14,6,0xe,7,7,0,0,0,0,0xa} (sum 97).
   - headers (`add_area_button` 0x8040a0, ret addrs = call+5): 0x80ca45 Nat.->"Club" (key 0x1000->8); 0x80cac9 Caps->"Pos" (key 0x4000->0x40); 0x80cb11 I.Gls->"Current" (key 0x8000); 0x80cb53 Form->"Potential" (key 0x10000); 0x80cb95 Morale and 0x80cbd8 Cond.: skip (pop ret, add esp 0x2c). Write new text into the buffer 0xde1f64 (it is what arg `text` points to). Age/Name/Inf/Value untouched. All new keys are in the handler's whitelist.
   - cells: 0x80e5ac (col 3): text `"  %s"` of club+0x38 (`club=[esi+0x39]`, else "  No Club"), data = club, id 0x7d5 (like General 0x80d9c0); 0x80e629 (col 5): `0x53ee50([esi+0x61], buf, 0xc8, 1)` as General; 0x80e668 (col 6) and 0x80e6a8 (col 7): stars or numbers (entry +0x29/+0x2a for the scout estimate; or `*(s16*)(pd+5)` / `*(s16*)(pd+7)`, pd=`[esi+0x61]`); 0x80e701 and 0x80e76f (cols 8, 9): skip (add_area_text pops 0x24).
   - sort: hook `SearchEditSession::get_current_results` 0x804a40 (arg4 callback): if ability and `[flags+4]==0x8000` -> 0x819620, `==0x10000` -> 0x8196e0 (existing comparators, scout stars; unscouted = 0 stars, ties by name). Club key 8 -> 0x819990 and Position key 0x40 -> 0x819da0 are picked by the game itself. If true CA/PA is shown, supply own comparators (cdecl, two `search_result*`, +0xc -> staff -> +0x61 -> +5/+7).
4. Text/panel hooks at 0x5e6d80 / 0x5e5df0 would also work for the cell part but cannot tell which column a text belongs to; the add_area_* call sites above give the column.
5. Not verified: popup auto-sizing for an 8th item (area rect is all zeros at 0x80a188, flags 0x130, so probably auto), whether bit 0x4000 survives search save/load unharmed (PLAYER_SEARCH::save 0x7b2360 / load 0x7b17e0 not read), and the 8-unit column text clipping (check "Pos" width visually).
