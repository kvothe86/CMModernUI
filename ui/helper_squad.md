## 2. Where the view is stored
- **Screen parameter 7** of the club screen: `ScreenManager(0xb74450)::get_screen_param(7)` (0x7ff010, thiscall, `push 7`), written with `set_screen_param(7, value, 0)` (0x7ff270, thiscall, ret 0xc). Not a global like the search screen; the tab is param 4 (1 = squad; handler jump table 0x4689e4: idx0 -> 0x467cd3 squad), the club is param 0 (Club\*), the sort key is param 8.
- Value is a **bit mask**: Traditional 1, Contract 2, Stats 4, More Stats 8, Attributes 0x10, Other 0x20; attribute sub-view bits 0x40 Physical, 0x80 Mental, 0x100 Goalkeeping, 0x200 Defensive, 0x400 Attacking (sub-popup tick tests 0x4585ed..0x458927, handler mask 0xfffff83f clears 0x7c0); **0x800 Penalty Takers = an overlay flag** (toggle, kept with the main view); **0x1000 Selection Info**. Free: 0x2000 and up (no test of 0x2000/0x4000 on param 7 seen in 0x456900 or 0x4671f0; **other readers of param 7 not searched**).
- Persistence: for a human club 0x456c16 writes params 7, 8, 0x18..0x1a, 9 into `HUMAN_MANAGER::get_squad_view_settings` 0x5fe950(0) (record `[0]` = view) and 0x453d60 `open_club_squad_screen` reads it back (`set_screen_param(7,*rec,0)`, line "if alt_view: |0x800"). So an Ability bit would be stored in the save game's human record (vanilla would show Other: harmless since only bit tests). Default value of a fresh record: **not found**.

## 3. Click on a View item (club screen handler 0x4671f0, cdecl(short widget), `esi` = widget index, -1 = none; returns eax)
- Squad branch: tab param 4 == 1 -> `dec; jmp [eax*4+0x4689e4]` at 0x467ccc -> 0x467cd3. There: p7 -> ebx (0x467cef..0x467d06), widget id = `Display::get_widget_id` 0x468b10 (thiscall ecx=display, push esi; at 0x467d8d); if 0 then id = word [0xdd6bde]; `cmp ax,7` **0x467d9d**; data = `ScreenManager::get_widget_action_data` 0x468b90 (thiscall ecx=0xb74450, push esi) at 0x467dad. (Same data are in the item table: id at `chan_display + 0xba966 + idx*0x18c`, data at `+0xba9a6`.)
- 0x467db2 `test ebx,eax; jne 0x467e69`: **view bit already set -> only 0x800 toggles (subtract, 0x467e74), everything else falls to 0x4687c1 (no change)**. This means Other cannot be clicked while Ability (with the Other/Selection bit) is active, unless a hook clears the bit first.
- Else: `cmp eax,0x80 / ja` ... data 0x80,0x100,0x200,0x400 and 0x40 -> **0x467df9** (`ebx = (ebx & 0xfffff83f) | data`); 0x800 -> 0x467e4d (`or bh,8`); 0x1000 -> 0x467e2c; data 1..0x40: byte table 0x468a04 (index data-1, only 1,2,4,8,0x10,0x20 -> entry 0, 0x40 -> entry 1, all other 2) into dword table 0x4689f8 = {0x467e2c, 0x467df9, 0x4687c1}.
- **0x467e2c**: `and ebx,0xffffefc0` (opcode `81 e3 c0 ef ff ff` at 0x467e2c; imm at 0x467e2e; clears 0x103f, keeps 0x40..0x800), `or eax,ebx`, `set_screen_param(7,eax,0)` at 0x467e3e, `edi = 0xfffffff5` (-11), `jmp 0x4687db`. 0x4687db frees the stack frame and returns **eax = edi**. **-11 (0xfffffff5) = rebuild the screen.**
- **Unknown data (e.g. 0x2000)**: byte table -> 2 (or the `cmp` chain at 0x467e1a/0x467e26 -> jne) -> **0x4687c1: `edi = -11`, no change, but the screen is rebuilt**. So an unhandled item is harmless; a hook is needed to store it.

## 5. Proposal: Ability = Selection layout + DLL overlay
Base the new view on **Selection Info** (bit 0x1000): Position is already column 3 (width 0xe, no change needed), Form/Morale/Cond. columns (widths 0xa/0xc/6) take Age/Current/Potential, Apps/Av R are blanked. State: **Ability = 0x2000 kept together with 0x1000** (so the game builds Selection untouched). `P7` = get_screen_param(7) / set_screen_param(7, v, 0).
1. **Menu item**: redirect the `call 0x55f990` at **0x456f7f** (Selection item) to a stub (thiscall, ecx kept, 18 stack args, `ret 0x48`; `ebx` = p7 at that point, `esi` = area): if `ebx & 0x2000` set arg1 to 2 (un-tick Selection), call the original; then call again with arg1 = `(ebx&0x2000) ? 0x2002 : 2`, arg14 = pointer to a buffer " Ability", arg17 = 0x2000 (id arg16 stays 7, area arg18 same). Ability then sits right under Selection. (Alternative: stub at 0x45725e after Other; then also un-tick Selection at 0x456f7f.) Popup auto-size for one more item: not verified.
2. **Click**: hook entry **0x4671f0** (prologue `6a ff 64 a1 00 00 00 00`, 8 bytes, relocatable). Only if `get_screen_param(4) == 1` (squad tab), widget != -1, `id == 7`, data = `get_widget_action_data(widget)`:
   - data == 0x2000: `P7 = (P7 & ~0x103f) | 0x1000 | 0x2000`, `set_screen_param(7, P7, 0)`, return **-11** (rebuild). Keep 0x800 and the attribute sub-bits.
   - data in {1,2,4,8,0x10,0x20,0x1000} and `P7 & 0x2000`: `set_screen_param(7, P7 & ~0x3000, 0)` first, then call the original (needed because of the `test ebx,eax` guard at 0x467db2; for 1,2,4,8,0x10,0x20 the game's mask only clears 0x103f). Otherwise call the original.
   - (Without hook for the clearing part: byte patch 0x467e2f `ef`->`cf` clears 0x2000 too, but the 0x467db2 guard still blocks re-clicking Selection.)
3. **Heading**: `call 0x803fd0` at **0x459679**: if `P7 & 0x2000` replace the text arg (esp+0xe8 buffer, "Selection Info") by "Ability Info" (optional).
4. **Headers** (only when `P7 & 0x2000`; hook `add_area_button` 0x8040a0 by return address = call+5; text buffer 0xde1f64 is the text arg): 0x45a248 Form -> "Age" key 0x4000; 0x45a28a Morale -> "Current"; 0x45a2cc Cond. -> "Potential" (their keys 0x100/0x200 would sort by Morale/Condition: use key 0x4000 or 4 instead; sort by ability needs a new comparator in 0x4841d0, **not found/not done**); 0x45a314 Apps and 0x45a35b Av R: skip (pop 0x2c, return). Pkd/Inf/Name/Position/Value untouched.
5. **Cells** (same hook style on `add_area_text` 0x804100, args area, col, row, ...; Staff\* = **edi**, row = esi, area = ebp; ret = call+5, callee pops 0x24): 0x45c46a col4: text = `"%d"` of `(s8)[edi+0x18]` (Age); 0x45c4a4 col5: Current stars; 0x45c507 col6: Potential stars; 0x45c54e col7 and 0x45c9fc col8: skip when view has 0x1000|0x2000 (0x45c9fc is also Other's col9: test `P7 & 0x1000` before skipping). Stars: PlayerData `pd = [edi+0x61]` (non-null in the loop), **CA = s16 at pd+5, PA = s16 at pd+7** (as in compare_players_by_ability 0x5d6220, checked); stars-from-CA mapping: **not found** (draw a number or compute own thresholds; the search screen's stars are the scout's estimate, not applicable here). Whether to hide values of other clubs' players (fog of war): not checked.
